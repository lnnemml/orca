Schema (proposed, not applied): `groups(id, name, parent_id NULL, …)` adjacency list + `jobs.group_id … ON DELETE SET NULL` (one group per job, a tree not tags). **Adjacency-list over closure-table/materialized-path** at hundreds-scale (rejected-alts recorded). **Jobs-survive:** group-delete orphans jobs to root (SET NULL, FK enforcement ON) and **promotes** sub-groups to the parent (so `parent_id` is NOT cascade — re-parent-then-remove in the command). Generic tree, **jobs-only FK now** (molecules/reactions deferred, zero churn); `group_id` **orthogonal** to the pipeline FKs (source_ensemble/reference/pathway). Term = "group", UI metaphor = "folder". Job **deletion** (DB vs DB+files, running-guard) is a separate 4.7 unit
